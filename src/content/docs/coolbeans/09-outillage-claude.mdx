L'environnement de travail Claude Code de Ludo : ce qu'il contient et
comment il est sauvegardé pour survivre à la perte d'une machine. Pour tout
réinstaller de zéro sans rien oublier.

## La sauvegarde : le repo dotfiles

Tout ce qui fait l'environnement Claude Code vit dans un repo GitHub privé :
**[github.com/ludobourgoin/dotfiles](https://github.com/ludobourgoin/dotfiles)**.
Si le Mac disparaît, ce repo permet de tout remonter sur une autre machine
en une trentaine de minutes, en suivant son guide `RESTORE.md`.

Ce qu'il contient :

| Dossier      | Contenu                                                                                                                                                                                                                                                                                                           |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `claude/`    | La configuration Claude Code : réglages (`settings.json`), hooks, commandes personnalisées, barre de statut, les **skills** (catalogue en page suivante), les agents, les **mémoires par projet** (le contexte que Claude accumule), la liste des plugins et la configuration des serveurs MCP (sans les secrets) |
| `dev/`       | Le `CLAUDE.md` global du dossier `/dev` (règles de travail, garde-fous)                                                                                                                                                                                                                                           |
| `shell/`     | Les fichiers de configuration du terminal (`zshrc`, `gitconfig`, statusline)                                                                                                                                                                                                                                      |
| `apps/`      | Les listes de réinstallation : `Brewfile` (Homebrew), applications installées, extensions Chrome et VS Code, packages npm globaux                                                                                                                                                                                 |
| `backup.sh`  | Le script qui régénère tout ce qui précède depuis la machine                                                                                                                                                                                                                                                      |
| `RESTORE.md` | Le guide de restauration pas à pas sur une machine neuve                                                                                                                                                                                                                                                          |

La sauvegarde n'est pas automatique : après tout changement de skill ou de
configuration, relancer `./backup.sh` à la racine du repo, puis commit et
push. Les secrets (tokens, clés SSH, fichiers `.env`) ne sont **jamais**
dans ce repo : ils se récupèrent depuis les dashboards des services ou se
régénèrent, comme détaillé dans `RESTORE.md`.

## Les skills

Un skill est un mode d'emploi que Claude charge à la demande pour une tâche
précise : il se déclenche tout seul quand la demande correspond à sa
description, ou à la main en tapant `/nom-du-skill`. Chaque skill est un
dossier `~/.claude/skills/<nom>/SKILL.md`, sauvegardé dans le repo dotfiles.
S'y ajoutent des plugins tiers installés depuis leurs marketplaces
(superpowers, context-mode, claude-seo, code-review), qui se réinstallent
automatiquement depuis la liste conservée dans dotfiles.

La liste complète, par catégorie, avec l'emplacement de chacun et les mots
qui le déclenchent : [Catalogue des skills](/docs/coolbeans/catalogue-skills).

## Les connexions aux applications

Claude se branche aux applications (Figma, Gmail, Notion, Linear…) par des
serveurs MCP. Ces serveurs arrivent par trois sources, et une même
application peut arriver par plusieurs à la fois. Chaque doublon demande
alors sa propre connexion, d'où des dizaines de demandes d'autorisation au
démarrage.

| Source                | Où ça se règle                                                                 | Ce qui y vit                                                                                       |
| --------------------- | ------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| Connecteurs claude.ai | [claude.ai/customize/connectors](https://claude.ai/customize/connectors)       | Figma, Gmail, Agenda, Drive, Sheets, Notion, Slack, Asana, Webflow, Shopify, Ahrefs, Sentry        |
| Serveurs locaux       | `~/.claude.json`, avec la commande `claude mcp`                                | Sanity, Relume, Linear, Cloudflare, Granola, HubSpot, Clerk, Make, google-docs, astro-docs         |
| Plugins               | `/plugin` dans Claude Code. Les plugins synchronisés viennent du compte claude.ai | Des skills, et parfois leurs propres serveurs                                                   |

### La règle : une application, une source

1. **Le connecteur claude.ai d'abord.** Il s'autorise une seule fois, sur
   claude.ai, et sert partout : terminal, extension VS Code, app desktop,
   web.
2. **Un serveur local seulement quand claude.ai n'en propose pas**, comme
   Sanity, Linear ou Cloudflare.
3. **Un plugin sert pour ses skills.** Ses serveurs en double sont bloqués.

### Ce qui a été réglé le 2026-10-01

- Les plugins `sales`, `marketing` et `productivity`, synchronisés depuis
  le compte claude.ai, sont désactivés sur le Mac. Aucun de leurs skills
  n'avait jamais servi. Ils restent sur le compte claude.ai.
- Les plugins `design` et `figma` sont gardés pour leurs skills
  (`design-critique`, `figma-use`). Leurs 10 serveurs en double sont bloqués
  dans `~/.claude/settings.json`, sous la clé `deniedMcpServers` : Figma,
  Slack, Notion, Asana, Gmail, Agenda, Linear, Atlassian, Intercom.
- Ces réglages sont sauvegardés dans le repo dotfiles.

### Revenir en arrière

Rien n'a été supprimé.

- Réactiver un plugin : `claude plugin enable sales@synced`.
- Débloquer un serveur : retirer sa ligne de `deniedMcpServers`.
- Retrouver un plugin retiré du compte : il se réinstalle depuis le
  catalogue « knowledge-work-plugins » de claude.ai.

### Quand un connecteur disparaît d'une session

Les connecteurs claude.ai se chargent au démarrage de chaque session. Si le
réseau coupe à ce moment, Claude Code réessaie trois fois, puis s'en passe
jusqu'à la fin de la session. L'autorisation n'est pas en cause : il n'y a
rien à reconnecter sur claude.ai. Il suffit d'ouvrir une nouvelle
conversation dans l'extension ou de relancer `claude` dans le terminal.

Le terminal et l'extension VS Code sont deux instances distinctes : `/mcp`
dans l'un ne dit rien des connexions de l'autre.
