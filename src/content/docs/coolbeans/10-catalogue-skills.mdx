La liste complète des skills disponibles dans Claude Code, rangés par
catégorie, avec pour chacun son emplacement et ce qui le déclenche. Pour
retrouver le bon outil sans fouiller le disque, et pour savoir quoi écrire
pour l'appeler.

L'environnement qui héberge tout ça et sa sauvegarde sont décrits dans
[Outillage Claude](/docs/coolbeans/outillage-claude).

## Comment un skill se déclenche

Un skill est un mode d'emploi que Claude charge à la demande. Il porte une
`description` en en-tête, et c'est **elle seule** qui décide du
déclenchement automatique : si la demande ressemble à cette description,
Claude ouvre le skill sans qu'on ait rien à demander.

Deux façons de l'appeler :

1. **Automatique** : écrire une phrase qui correspond à la description. Les
   colonnes « Se déclenche sur » ci-dessous donnent les formulations
   réellement inscrites dans chaque skill.
2. **À la main** : taper `/` dans le prompt puis le nom du skill. Utile
   quand le déclenchement automatique ne part pas, ou pour forcer un skill
   précis.

<Callout type="tip">
  Les skills de dev et d'infra (Astro, Cloudflare, auth) n'ont pas de mots-clés : ils se déclenchent
  au contexte, dès qu'on touche au sujet dans un projet qui l'utilise. Les packs marketing et sales
  achetés sont décrits en anglais : ils partent mieux sur le vocabulaire anglais, ou en
  `/nom-du-skill`.
</Callout>

## Où vivent les skills

Quatre emplacements, quatre portées différentes. Tout ce qui n'est pas
indiqué autrement dans les tableaux vit dans `~/.claude/skills/`.

| Emplacement                             | Contenu                                                                     | Portée                                | Sauvegarde                        |
| --------------------------------------- | --------------------------------------------------------------------------- | ------------------------------------- | --------------------------------- |
| `~/.claude/skills/`                     | 141 skills, un dossier `<nom>/SKILL.md` par skill, avec ses `references/`   | Tous les projets, toutes les sessions | Repo `dotfiles` (`./backup.sh`)   |
| `~/dev/coolbeans-claude-skills/skills/` | Les skills publiés en open source : `linear`, `doc-client`                  | Source de vérité de ces deux skills   | Repo GitHub public                |
| `~/.agents/skills/`                     | Skills partagés avec les autres agents de la machine : GSAP (8), Sanity (2) | Liés dans `~/.claude/skills/`         | Le lien seulement, pas le contenu |
| `~/.claude/plugins/cache/`              | Les skills livrés par les plugins installés depuis leurs marketplaces       | Tous les projets                      | Liste des plugins dans `dotfiles` |

Douze skills sont des **liens** et non des copies : `linear`, `doc-client`,
les deux Sanity et les huit GSAP. Les éditer met à jour leur source du même
coup, et la sauvegarde dotfiles n'enregistre que le lien : une restauration
sur machine neuve suppose d'avoir d'abord remonté `coolbeans-claude-skills`
et `~/.agents/skills/`.

Un repo peut aussi porter ses propres skills dans `<projet>/.claude/skills/`,
prioritaires sur ceux du même nom. Aucun projet n'en a aujourd'hui : les
skills Clerk que `coolbeans` embarquait doublonnaient les skills user, ils
ont été retirés le 2026-08-29.

## Conventions d'emplacement

Trois règles tenues au dernier inventaire (2026-08-29), à respecter pour
que le catalogue reste lisible :

**Un skill publié vit dans son repo public**, et `~/.claude/skills/` n'en
porte qu'un lien. C'est le montage de `linear` et de `doc-client` : pas de
copie de travail qui dérive de la version publiée.

**Pas de skill de projet qui doublonne un skill user.** Un skill utile à
plusieurs projets monte dans `~/.claude/skills/`, où il est sauvegardé.
`<projet>/.claude/skills/` est réservé à ce qui n'a de sens que dans ce
repo.

**Un skill installé mais non lié n'existe pas.** Ce que d'autres outils
posent dans `~/.agents/skills/` reste invisible de Claude Code tant qu'un
lien ne le remonte pas dans `~/.claude/skills/`.
