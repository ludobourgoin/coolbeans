La référence technique de la chaîne devis. Le **workflow** (brief, chiffrage,
passes 1 et 2, envoi) est documenté sur la page Workflow CRM — ici, l'outillage qui
le porte. L'ancien module de chiffrage manuel (configurateur, catalogue par
niveaux, publication KV) a été supprimé le 2026-08-17 : le devis se dérive
désormais d'un projet Linear via la skill `devis`.

## Ce que c'est

Trois pièces :

- **Le devis** : un fichier YAML dans `src/content/devis/`, écrit par la
  skill ; le nom du fichier devient l'adresse `/devis/<slug>`.
- **Le cockpit** `/espace/devis` : lecture seule, il liste les devis publiés
  avec leur statut et la réponse du client. Aucune création ni édition ici.
- **Les Réglages** `/espace/devis/reglages` : la source de vérité des prix,
  lue par la skill au moment de composer.

## Le cockpit

Le statut d'un devis est **dérivé, jamais stocké** :

| Statut | Condition |
| --- | --- |
| Publié | YAML en prod, sans champ `envoi` |
| Envoyé | `envoi.date` présent dans le YAML (écrit par la skill à l'envoi) |
| Répondu | Une ligne existe en D1 pour ce slug — prioritaire, même sans `envoi` |

Chaque ligne du cockpit relie la page publique, le projet Linear et
l'affaire CRM (champs `linear.projet` / `linear.affaire` du YAML), et
déplie la dernière réponse du client quand elle existe.

## Les Réglages

Clé KV `pilotage:reglages` (binding `PORTAL_KV`), éditée par l'action
`reglages.sauvegarder` — garde admin doublée : la page vérifie le rôle, et
l'action serveur refait la même vérification de son côté.

| Champ | Rôle |
| --- | --- |
| `tjm`, `heuresJour` | Base du calcul : estimates (1 pt = 1 h) ÷ heures/jour × TJM |
| `marcheBas`, `marcheHaut` | Fourchette de marché, sert à la fourchette de la passe 1 |
| `joursSemaine`, `semainesMarge` | Conversion charge → semaines de planning |
| `chargesPct` | Net estimé après charges |
| `gestionPct` | Gestion de projet : **+15 % sur la totalité du projet** |
| `urgencePct` | Urgence : +20 %, **affichée au devis en valeur absolue (€)** avec son tooltip |
| `affinite.baisse` / `.hausse` | Envie de travailler avec le client : −20 % / +20 % |
| `segments` | Postures par type de client (agence, designer, PME, TPE, association) |
| `devisTexts` | Textes de base : stack recommandée, règlement, ce que ça comprend, hors périmètre, tooltip d'urgence |

À la première lecture, l'ancienne clé `pilotage:catalog` est migrée en
douceur (jamais réécrite ni supprimée) ; une entrée corrompue retombe
silencieusement sur les défauts. Le calcul lui-même vit dans
`src/lib/chiffrage/calc.ts` (`calculerDevis`), pur et testé — la skill peut
l'exécuter via `npx tsx` plutôt que de calculer de tête.

### Ces réglages sont globaux

Le `tjm` est **une valeur unique lue par tous les devis**. Le modifier pour
encoder le tarif d'un client précis reprice en silence tous les projets en
statut Proposal. Un tarif qui ne vaut que pour un client se pose dans le bloc
Chiffrage de son projet : `Réduction` nommée (visible sur la page) ou prix
retenu posé à la main (muet). `Gestion de projet` est un booléen par projet,
à `non` par défaut : sur un lot revendeur, où c'est l'agence qui porte la
relation client, les +15 % n'ont pas lieu d'être.

## Chiffrer un petit lot

Deux biais se croisent sur les prestations de quelques heures, et ils vont en
sens inverse — d'où l'illusion d'avoir chiffré juste.

**Le TJM sous-facture.** Un lot de 3 heures porte le même coût de mise en
route qu'un lot de 3 jours : comprendre la demande, ouvrir le projet,
recetter, publier, facturer. Le taux réellement pratiqué et accepté sur les
petits lots tourne autour de 106 €/h, là où un TJM de 500 € en donne 71.

**Le Fibonacci sur-estime.** L'échelle de la skill `linear` a un plancher à
1 point = 1 heure : un lot de 4 h 30 découpé en quatre lignes de 20 à 40
minutes ressort à 6 points. Sur ces lots, c'est le prix retenu à la main qui
fait foi, pas la somme des estimates.

La méthode : chiffrer le temps tâche par tâche en minutes, convertir, puis
**vérifier le €/h obtenu** contre l'historique de facturation
(`~/.claude/skills/devis/references/historique-facturation.md`). Sur un client
déjà servi, un écart de plus de 30 % avec sa dernière prestation se justifie
ou se corrige — il ne se découvre pas dans la conversation.

## Le schéma YAML

Format fait pour écrire vite : sections libres combinant texte, liste,
budget et planning ; le gras s'écrit comme en Markdown ; une ligne de budget
sans `prix` s'affiche « Inclus ».

Ajouts du 2026-08-17 :

- **`tooltip`** sur les items de liste (`{ texte, tooltip }`), les lignes de
  budget et les notes : un marqueur ⓘ accessible (survol et focus) qui sort
  l'explication du fil principal — la justification du +20 % d'urgence, le
  contenu d'un poste.
- **`envoi { date, destinataire }`** et **`linear { projet, affaire }`** :
  champs internes lus par le cockpit, **jamais rendus** sur la page
  publique.

Présentation : un **montant total unique** — les lignes du périmètre sont
sobres et sans prix, seules les options affichent le leur. On vend un
projet, pas du temps.

## Les réponses client

La page publique d'un devis porte le formulaire de réponse
(`src/pages/api/devis-reponse.ts`) : la réponse s'écrit d'abord dans la
table D1 `devis_reponses` (base `PORTAL_DB`, migration `0002`), puis part en
notification mail via Resend. Si l'écriture D1 échoue, le mail part quand
même — la notification prime, l'erreur est loguée. La table est append-only.

Toutes les pages devis sont exclues des moteurs de recherche et du sitemap :
accessibles à qui possède le lien, rien de plus.

## Référence technique

| Élément | Emplacement |
| --- | --- |
| Cockpit et Réglages | `src/pages/espace/devis/` (index, reglages) |
| Éditeur de Réglages | `src/components/chiffrage/ReglagesEditor.tsx` |
| Action serveur (garde admin) | `src/actions/index.ts` (`reglages.sauvegarder`) |
| Calcul | `src/lib/chiffrage/` (calc, blocChiffrage, store, schemas, defaults, types) |
| Statut et réponses | `src/lib/devis/` (statut, reponses) |
| Devis YAML (contenu) | `src/content/devis/*.yaml`, schéma dans `src/content.config.ts` |
| Rendu devis | `src/pages/devis/[slug].astro`, tooltips via `src/components/ui/Tooltip.astro` |
| Réponse au devis | `src/pages/api/devis-reponse.ts`, table `devis_reponses` (migration `0002`) |
| Ancienne route supprimée | `/devis/[client]/[projetId]` — aucun devis KV n'était en circulation |
